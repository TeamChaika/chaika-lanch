# Чайка Обеды

Адаптивная вёрстка сервиса доставки готовых обедов для Ялты, Севастополя и Симферополя. Next.js, React, TypeScript и обычный CSS. Шрифты и логотип хранятся в проекте. Фотографии отдаются из Timeweb S3 в WebP; локальные WebP сохранены как резерв.

## Открыть сайт

Требуется Node.js 22 или 24 LTS и npm. Версия также указана в `.nvmrc`.

```bash
npm install
npm run dev
```

Откройте http://127.0.0.1:3000. Чтобы остановить сервер, нажмите Ctrl+C в терминале.

## Заменить логотип

Замените **`public/brand/logo.png`** своим PNG-файлом с таким же именем. Лучше использовать изображение с прозрачным фоном без больших пустых полей. Сейчас здесь лежит исходный CHAIKATEAM, предоставленный вами.

Обновите страницу. Если браузер показывает старую картинку, выполните обновление без кеша. Другой путь или формат логотипа можно указать в `src/data/site.ts` в поле `logo`. Размеры логотипа на компьютере и телефоне задаются селектором `.logo` в `src/app/globals.css`.

## Возможности

- Двенадцать комплектов по 450–550 ₽, подробный состав и аллергены.
- Своё меню на каждый будний день: по 2–3 комплекта без повторов в течение недели. В недельном выборе — только блюда соответствующего дня.
- Выбор из пяти ближайших рабочих дней и сбор заказа на несколько дней.
- Корзина с количеством и сохранением в браузере после обновления страницы.
- Выбор города и адреса, демонстрационное оформление и подтверждение.
- Предварительный расчёт обедов для команды.
- Мобильная корзина, адаптивные формы, управление диалогами с клавиатуры.
- Одна выпечка бесплатно при заказе на все пять ближайших рабочих дней. Подарок появляется автоматически, сохраняется при обновлении и исчезает, если убрать один из дней. Количество порций на один день не влияет на это условие. Подарок не увеличивает цену или стоимость доставки.

## Меню по дням

| День | Комплекты |
| --- | --- |
| Понедельник | Домашний, Классический, Особенный |
| Вторник | Индейка с булгуром, Тефтели с пастой, Жаркое с картофелем |
| Среда | Плов с курицей, Рыба с кускусом |
| Четверг | Котлеты с пюре, Бефстроганов с рисом |
| Пятница | Фаршированные перцы, Курица с грибами |

Расписание повторяется каждую неделю. Редактируйте `weeklyMenu` в `src/data/menu.ts`: ключи 1–5 соответствуют понедельнику–пятнице, значения — идентификаторам обедов. При изменении меню ранее сохранённые позиции, недоступные на свою дату, исключаются из корзины.

Оригинал фотографии подарка — `assets/images/weekly-gift.png`, предоставленная вами. Название и изображение можно поменять в `site.weeklyGift`. Текущая механика — одна выпечка на весь недельный заказ, включая коллективный; размер подарка для групп можно изменить отдельно.

## Границы демонстрации

Заказы и заявки **никуда не отправляются**, оплата не производится. Персональные данные используются только в открытой вкладке; в localStorage сохраняются только позиции корзины. Флаг `demo` в настройках сам по себе не подключает рабочий приём заказов.

Меню, состав, вес и фотографии иллюстративные. Перед публикацией замените их на реальные данные кухни. Доставка 100 ₽ за каждый день заказа и интервалы указаны для примера. Реальные зоны, расписание, доступность блюд и тарифы пока не проверяются сервером. Пять ближайших рабочих дней рассчитываются в часовом поясе Крыма; ограничение приёма заказов по времени ещё не подключено.

Для запуска необходимо подключить сервер заказов и оплату, заменить примерные условия и контакты, добавить необходимые документы. Индексирование поисковиками пока отключено через `robots` в `src/app/layout.tsx`.

## Сборка для хостинга

```bash
npm run build
```

Готовый статический сайт появляется в **`out/`**. Содержимое этой папки можно загрузить на хостинг статических сайтов. После изменения исходников или логотипа сборку нужно повторить.

Для локального просмотра сборки сначала остановите сервер разработки, затем:

```bash
npm run preview
```

## Фотографии: WebP и Timeweb S3

Все 12 обедов и выпечка подготовлены в размерах 160, 320, 640, 960 и 1280 px, с качеством WebP 80. Выпечка ограничена исходными 900 px. Браузер выбирает подходящий размер по ширине экрана и плотности пикселей. Небольшие изображения в корзине и недельном выборе используют миниатюры; скрытый мобильный баннер не скачивается.

Самые большие версии всех 13 фото: **37 510 563 → 2 683 208 байт (−92,8%)**. Суммарный размер всех 64 вариантов — **5 596 636 байт**, но браузер загружает только выбранные версии. Данные по каждому файлу: `docs/image-sizes.json`.

Фото опубликованы в уже существующем публичном хранилище Timeweb S3, в отдельной папке `chaika-lanch/images/optimized/`. Новое хранилище и отдельный CDN не создавались. Объекты имеют `Content-Type: image/webp` и `Cache-Control: public, max-age=31536000, immutable`. Хеш в имени меняется вместе с изображением, поэтому новое фото не застревает в кеше. При ошибке S3 компонент переключается на локальную WebP-копию.

Чтобы заменить фотографию:

1. Замените PNG в `assets/images/`, сохранив имя. Для нового блюда добавьте PNG и укажите `/images/имя.webp` в `src/data/menu.ts`.
2. Выполните `npm run images:optimize`: будут созданы WebP, манифест и отчёт размеров. Исходные PNG не попадут в папку публикации.
3. Передайте `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY` через окружение **только локального процесса загрузки** и выполните `npm run images:upload`. Скрипт загружает только файлы манифеста в папку `chaika-lanch`, проверяет публичную доступность и не меняет настройки бакета. Ключи нельзя добавлять в Git, настройки браузера или `NEXT_PUBLIC_*`.
4. Запустите `npm run build`, отправьте изменения в Git и повторно разверните приложение в Timeweb. Сначала загружаются файлы, затем публикуется сайт.

Для работы только с файлами приложения задайте пустой `baseUrl` в `src/data/image-hosting.json` и пересоберите сайт. При этом S3-загрузка не нужна. Старые файлы с хешами не удаляются автоматически, чтобы не ломать ранее опубликованные страницы.

```bash
npx playwright install chromium
npm run test:e2e
```

Тесты проверяют покупательский сценарий, расчёты, сохранение корзины, ассортимент по дням, выдачу и отмену подарка, выбор города, клавиатурное управление, узкий экран, responsive WebP и резервную загрузку при недоступности S3.
