# Чайка Обеды

Сайт с админкой меню для сервиса доставки готовых обедов для Ялты, Севастополя и Симферополя. Next.js, React, TypeScript и обычный CSS. Шрифты и логотип хранятся в проекте. Фотографии отдаются из Timeweb S3 в WebP; локальные WebP сохранены как резерв.

## Открыть сайт

Требуется Node.js 22 или 24 LTS и npm. Версия также указана в `.nvmrc`.

```bash
npm install
# Заполните .env.local по .env.example; для локального меню можно указать MENU_STORE=local.
npm run dev
```

Откройте http://127.0.0.1:3000. Чтобы остановить сервер, нажмите Ctrl+C в терминале.

## Заменить логотип

Замените **`public/brand/logo.png`** своим PNG-файлом с таким же именем. Лучше использовать изображение с прозрачным фоном без больших пустых полей. Сейчас здесь лежит исходный CHAIKATEAM, предоставленный вами.

Обновите страницу. Если браузер показывает старую картинку, выполните обновление без кеша. Другой путь или формат логотипа можно указать в `src/data/site.ts` в поле `logo`. Размеры логотипа на компьютере и телефоне задаются селектором `.logo` в `src/app/globals.css`.

## Админка меню

Откройте `/admin` и войдите по паролю владельца. Меню, цены, позиции и фото меняются без Git и пересборки. Пошаговая инструкция: [docs/admin-guide.md](docs/admin-guide.md).

Локальный режим `MENU_STORE=local` сохраняет меню в `.local-menu/` и предназначен для разработки; загрузка фотографий в нём недоступна.

Данные хранятся в существующем Timeweb S3, а сервер проверяет пароль и публикует изменения. Текущая версия требует серверного запуска Next.js; статический экспорт больше не поддерживается.

## Возможности

- Двадцать комплексов из Excel по 550 ₽: салат 100 г, суп 250 г, горячее 300 г и компот 200 г.
- Четыре недели по пять рабочих дней, по одному комплексу в день. Календарь привязан к 21 сентября 2026 года; после четвёртой недели цикл повторяется.
- Просмотр четырёх календарных недель и заказ выбранной недели. Прошедшие дни недоступны, по выходным календарь начинается со следующего понедельника.
- Корзина с количеством и сохранением в браузере после обновления страницы.
- Выбор города и адреса, демонстрационное оформление и подтверждение.
- Предварительный расчёт обедов для команды.
- Мобильная корзина, адаптивные формы, управление диалогами с клавиатуры.
- Одна выпечка бесплатно при заказе на пять разных рабочих дней. Подарок появляется автоматически, сохраняется при обновлении и исчезает, если убрать один из дней. Количество порций на один день не влияет на это условие. Подарок не увеличивает цену или стоимость доставки.

## Меню на четыре недели

Источник: `Комплексные_обеды_меню_на_месяц.xlsx`, лист «Меню на месяц», строки 4–23. Все 80 названий блюд перенесены дословно в `src/data/monthly-menu.json`. В горячее входят основа 100 г, гарнир 150 г и соус 50 г. Сумма весов компонентов — **850 г**; указанные внизу Excel 950 г противоречат этим весам и не используются.

Цена **550 ₽** подтверждена владельцем. Дата первой недели **2026-09-21** выбрана как ближайший понедельник, поскольку дата не была указана; её можно поменять в админке (должна быть понедельником); `site.menuCycleStartsOn` задаёт только исходное значение. Цикл не сбрасывается при смене месяца. Старые демонстрационные блюда и позиции, не соответствующие дате, удаляются из сохранённой корзины.

Фото: [предоставленная папка Яндекс Диска](https://disk.yandex.ru/d/uUwCF4Nwc4YFoA). Получены 46 веб-версий, включая 35 кадров обедов и 11 портретов. Архив оригинальных JPEG и крупный просмотр не загрузились. Доступные файлы имеют ширину 445–1280 px и уже отдаются Яндексом в WebP; они сохранены без увеличения разрешения и подготовлены в нескольких размерах. Исходники `lunch-photo-001.webp`–`lunch-photo-046.webp` соответствуют номерам в папке. На сайте используются пять кадров обедов: 003, 007, 016, 019 и 029. Портреты и другие ракурсы подготовлены для дальнейшего использования.

В папке нет точного соответствия каждому из 20 комплексов. Подпись на фото сообщает «Пример подачи · состав в меню». Названия, порции и напитки берутся из Excel; неподтверждённые калории, рецептуры и аллергены не добавлены.

Оригинал фотографии подарка — `assets/images/weekly-gift.png`, предоставленная вами. Название и изображение можно поменять в `site.weeklyGift`. Текущая механика — одна выпечка на весь недельный заказ, включая коллективный; размер подарка для групп можно изменить отдельно.

## Границы демонстрации

Заказы и заявки **не отправляются на кухню**. Подключён тестовый контур QR Manager для СБП: `QRM_MODE=sandbox` и серверный `QRM_API_KEY` включают создание QR, платёжную страницу и проверку статуса. Деньги не списываются. Без этих настроек остаётся прежнее демонстрационное оформление. Подробнее: [QR Manager](docs/qrmanager.md), включая обнаруженный сбой внешнего стенда и порядок проверки.

Персональные контакты используются только в открытой форме и не передаются в общую тестовую среду. В localStorage сохраняются корзина и отметки обработанных тестовых оплат, в sessionStorage — идентификатор попытки. Тестовые операции хранятся в S3 в зашифрованном виде. Флаг `demo` в настройках сам по себе не подключает рабочий приём заказов.

Меню и веса перенесены из таблицы кухни. Фотографии показывают примеры подачи; точная рецептура и аллергены в источнике отсутствуют. Доставка 100 ₽ за каждый день заказа и интервалы указаны для примера. Перед созданием тестового платежа сервер проверяет цену, доступность блюд в опубликованном меню и даты четырёх недель в часовом поясе Крыма. Проверка реальных зон доставки и ограничение приёма по времени ещё не подключены.

Для запуска необходимо подключить сервер заказов и оплату, заменить примерные условия и контакты, добавить необходимые документы. Индексирование поисковиками пока отключено через `robots` в `src/app/layout.tsx`.

## Сборка для хостинга

```bash
npm run build
```

Серверная сборка появляется в `.next/`. Запуск: `npm start` (порт из `PORT`, по умолчанию 3000). Нужны серверные переменные из `.env.example`. После изменения кода или логотипа сборку повторяют; изменения меню из админки пересборки не требуют.

Для локального просмотра сборки сначала остановите сервер разработки, затем:

```bash
npm run preview
```

Настройки: **Backend / Dockerfile**, Node.js **24**, Next.js с SSR, порт 3000. Сборка и запуск описаны в корневом `Dockerfile`. Тариф 2731: 1 CPU, 1 ГБ RAM, 15 ГБ диска, **510 ₽/месяц** на момент подключения 18 сентября 2026 года. Существующее S3 оплачивается отдельно. Серверные переменные: `APP_ORIGINS`, `SESSION_SECRET`, `OWNER_PASSWORD_HASH`, `S3_ENDPOINT`, `S3_BUCKET`, `S3_PREFIX`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`. В `APP_ORIGINS` перечислены основной и технический HTTPS-адреса через запятую. `CMS_STORAGE_PREFIX` в рабочем приложении не задаётся. Автодеплой выключен.

Docker включает `NEXT_STANDALONE=1`: Next.js собирает минимальный сервер и нужные зависимости. Финальный образ содержит `.next/standalone`, `.next/static` и `public`, запускается от пользователя `node` и не выполняет `npm prune`. `.dockerignore` разрешает только исходники и входные файлы сборки: `.env*`, ключи, тестовые данные и оригиналы фото не передаются в Docker. Переменные S3 и пароль задаются при запуске, сборка их не требует. Локальные `npm run build` и `npm start` сохраняют обычный режим Next.js. Проверку зависимостей `npm audit` выполняют отдельно.

## Фотографии: WebP и Timeweb S3

Изображения подготовлены в размерах 160, 320, 640, 960 и 1280 px с качеством WebP 80, не превышая доступное исходное разрешение. Браузер выбирает подходящий размер по ширине экрана и плотности пикселей. В корзине и недельном выборе используются миниатюры; скрытый мобильный баннер не скачивается.

Для 46 новых снимков создано **179 вариантов WebP**, суммарно **4,593,284 байт**. Браузер скачивает только выбранные версии, а не весь набор. Пофайловые размеры: `docs/image-sizes.json`. Старые изображения сохранены для предыдущих публикаций.

Фото опубликованы в уже существующем публичном хранилище Timeweb S3, в отдельной папке `chaika-lanch/images/optimized/`. Новое хранилище и отдельный CDN не создавались. Объекты имеют `Content-Type: image/webp` и `Cache-Control: public, max-age=31536000, immutable`. Хеш в имени меняется вместе с изображением, поэтому новое фото не застревает в кеше. При ошибке S3 компонент переключается на локальную WebP-копию.

Владелец меняет фото кнопкой «Загрузить фото» в `/admin`. Сервер принимает JPG, PNG и WebP до 12 МБ, проверяет содержимое, удаляет метаданные и создаёт несколько WebP без увеличения размера. Они хранятся в `chaika-lanch/images/uploads/`. У загруженных фото нет локального резерва: храните оригиналы у себя.

Для разработчика — замена исходных фотографий через Git:

1. Замените PNG, JPEG или WebP в `assets/images/`, сохранив имя. Для нового блюда добавьте изображение и укажите `/images/имя.webp` в `src/data/menu.ts`.
2. Выполните `npm run images:optimize`: будут созданы WebP, манифест и отчёт размеров. Исходные изображения не попадут в папку публикации.
3. Передайте `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY` через окружение **только локального процесса загрузки** и выполните `npm run images:upload`. Скрипт загружает только файлы манифеста в папку `chaika-lanch`, проверяет публичную доступность и не меняет настройки бакета. Ключи нельзя добавлять в Git, настройки браузера или `NEXT_PUBLIC_*`.
4. Запустите `npm run build`, отправьте изменения в Git и повторно разверните приложение в Timeweb. Сначала загружаются файлы, затем публикуется сайт.

Для работы только с файлами приложения задайте пустой `baseUrl` в `src/data/image-hosting.json` и пересоберите сайт. При этом S3-загрузка не нужна. Старые файлы с хешами не удаляются автоматически, чтобы не ломать ранее опубликованные страницы.

## Проверки

```bash
npm run typecheck
npm run lint
npx playwright install chromium
npm run test:e2e
```

Тесты проверяют покупательский сценарий, расчёты, сохранение корзины, ассортимент по дням, выдачу и отмену подарка, выбор города, клавиатурное управление, узкий экран, responsive WebP и резервную загрузку при недоступности S3. Они запускаются в Chromium для компьютера и с параметрами мобильного устройства.


Проверки админки меняют данные, поэтому запускаются **только на localhost с отдельным тестовым префиксом S3**. Задайте `CMS_STORAGE_PREFIX` с `-test-` в имени и временный пароль; основной `S3_PREFIX` используется для тестовых фото с уникальными именами. Трассировки запросов входа отключены.

```bash
# Сервер на localhost:3002 уже запущен с теми же переменными.
ADMIN_TEST_PASSWORD_FILE=research/admin/test-password.txt node --env-file=.env.local node_modules/@playwright/test/cli.js test --config playwright.admin.config.ts
```

Первичный пароль для нового сервера генерируется локально командой `node scripts/create-owner-env.mjs`. Скрипт не выводит пароль: два файла в `research/owner-setup/` содержат данные для защищённой передачи в настройки сервера и владельцу. Повторный запуск не перезаписывает существующие файлы. Настройка не меняет пароль действующего владельца.
